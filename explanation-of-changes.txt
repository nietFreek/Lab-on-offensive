Summary of Changes:
I have finalized the SSL Stripping logic and interaction cleanup in SSLFilter.py. The implementation is now functionally complete for a Proof-of-Concept attack.

1. SSL Stripping Core Logic (Completed):
   - Implemented 'Upgrade to SSL' mechanism. 
   - When the victim sends an HTTP request and the server responds with a 301 Redirect to HTTPS, the filter now intercepts this redirect.
   - The filter establishes a legitimate SSL/TLS connection to the server on Port 443.
   - The original HTTP request is then replayed over this encrypted tunnel.
   - The response is decrypted by us, downgraded (links rewritten from https:// to http://), and sent back to the victim as plain text. This keeps the victim on HTTP while we proxy HTTPS.

2. TCP Connection Management (Completed):
   - Added handle_fin filter: Properly handles graceful connection termination (FIN packets). It acknowledges the FIN, increments sequence numbers correctly, and closes the upstream socket.
   - Added handle_rst filter: Handles abrupt connection resets, ensuring sessions are deleted from memory and sockets are closed to prevent resource leaks.
   - Added proper logic to separate standard Data/ACK handling from connection teardown.

3. Request Handling:
   - Added Accept-Encoding: identity injection. We force the server to send plain text (no gzip) so we can perform string replacement on the body content.
   - Implemented request payload caching (last_request_payload) to enable the seamless replay of requests after an SSL upgrade.

Status:
- The SSLFilter.py is now ready for experimental testing.
- It correctly handles the 'Victim (HTTP) <-> Attacker (Proxy) <-> Server (HTTPS)' flow.
